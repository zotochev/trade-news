## Принятые решения (с обоснованием, чтобы не переобсуждать)

- SQLite вместо PostgreSQL на старте; схема переносима (SQLAlchemy Core + Alembic).
- Запуск через systemd, не docker-compose (решение заказчика).
- Админка: только `127.0.0.1:ADMIN_PORT` (10000), без `ADMIN_HOST`; наружу nginx + HTTPS +
  `auth_basic`, домен `kainode.duckdns.org`. POST с чужого Origin отклоняется.
- Подписка в боте без подтверждения и без ролей; владелец получает всё и видит уведомления
  о подписках и отписках. Кнопку «отправить мне» в админке заказчик не захотел.
- Правила рассылки хранятся в БД (`settings`, ключ `delivery_rules`) и меняются в админке.
  Стартовые: importance ≥ 3, только с направлением, существенные события (включая insider).
  «Мои активы» (watchlist) заказчику не подходят: нужны сигналы для краткосрочных сделок
  (часы и дни) по любым компаниям, а не по списку.
- Form 4: разбор XML, в LLM только сделки на рынке по порогам (config `form4_thresholds`).
- Хранение: неразмеченное удаляется через 30 дней, размеченное через 365, журналы через 90.
- Gemini-клиент перенесён из проекта ict-monitor (`PycharmProjects/ict-monitor`, там же
  исходные секреты). Сутки квоты Gemini начинаются в 08:00 UTC (наблюдение из ict-monitor).
- Контракт LLM дополнен: `event_type` = `insider`, `relevance.date_to_iso` для окон.

  4 — 3, 5 — 0. Порог 4 почти ничего не пропускает, 3 — около половины.
- Form 4: ~10% подач проходят фильтр по сумме; модель ставит крупным покупкам 4–5.
- Разметка: ~140 токенов на входе и ~223 на выходе на новость, ≈ $0.0006 по платным ценам;
  пачка 25 новостей = 1 запрос.
- Лента EDGAR иногда отвечает 10–30 с; `type=` в ленте фильтрует по префиксу (type=4 → 424B2…).

## Заметки для разработки

- В Windows-консоли вывод кириллицы и эмодзи из Python: `PYTHONIOENCODING=utf-8`.
- Невидимые символы (узкий неразрывный пробел, BOM) в коде задавать через `chr(0x...)`:
  при записи файлов инструментом escape-последовательности превращаются в сами символы.

- Правила кода: функции и dataclass вместо иерархий классов, SQLAlchemy Core, SQLite.
  Новый источник: файл в `trade_news/collectors/` + секция в `config.yaml` (см. README).
- Коммит → сразу `git push` (сервер деплоится через `git pull`).
- На сервере нет git identity: коммитить с `git -c user.name="Mikhail Zotochev"
  -c user.email="zotochev@gmail.com" commit ...` (как все коммиты репозитория).
- Живые проверки коллекторов — на временной базе: `DATABASE_URL=sqlite:///<scratch>/try.db
  trade-news db-upgrade && trade-news collect <source>`, чтобы не трогать боевую.
- Работать с заказчиком по одному шагу: предлагать варианты с рекомендацией и ждать выбора,
  не брать следующую задачу самостоятельно.
- RSS ЦБ: ленты отдают недели истории без курсора; записи старше `max_age_hours` сохраняются
  с `llm_skip`, иначе первый сбор отправил бы старые решения в LLM и Telegram как свежие.
  Рутина (операции, статистика) отсекается `llm.exclude`. BoE отдаёт 403 на User-Agent httpx.
- Marketaux (бесплатно): 100 запросов в сутки, 3 статьи на запрос. Опрос раз в 20 мин, жёсткий
  потолок `daily_request_budget` (80) в курсоре. Ключ только в URL (`api_token`): ошибки HTTP
  перевыбрасываются без URL. Самые свежие статьи в выдаче отстают примерно на 50 минут.
- CME FedWatch: пакет `cme-fedwatch` (сам ходит в CME/FRED через curl_cffi, мимо нашего
  лимитера). Итоги торгов раз в рабочий день; каждый новый снимок пишется в `rate_expectations`
  (через `Batch.rows`), прошлый снимок лежит в курсоре. Новость создаётся, если
  исход одного из 3 ближайших заседаний сдвинулся на >= 10 п.п. Первый запуск только сохраняет базу.
- FRED: ряды в `config.yaml`, наблюдения в `macro_observations` (первое значение, ревизии
  игнорируются). Доходности с `alert_bp` дают новость при дневном сдвиге (только последнее
  наблюдение, чтобы после простоя не слать старое). Ключ в URL: ошибки HTTP без URL.
- Календарь: снимки в `econ_events` только при смене прогноза или предыдущего значения. Факт
  для США: до выхода запоминается дата последнего наблюдения FRED, после выхода ждём новое
  (до 12 ч), считаем level/diff/m/m/y/y и создаём новость. Событие, впервые увиденное после
  выхода, пропускается. FRED обновляется с задержкой, поэтому новость выходит позже релиза.
- Рассылка: приоритетные сигналы (`always_sources`: календарь, FedWatch, FRED;
  `always_event_types`: rate_decision) идут без порогов, отдельными сообщениями и первыми;
  остальные новости одного прохода — одной сводкой. `max_per_hour` считает сообщения.
  В админке `always_*` пока не редактируются (при сохранении правил берутся значения по умолчанию).
- `alembic.ini` смотрит в `data/trade_news.db`: `alembic revision --autogenerate` сравнивает
  с боевой базой (только чтение).
- Не запускать локально `trade-news run` при работающем сервере: второй процесс, опрашивающий
  того же бота, получит 409 и будет мешать серверу. Для проверок: `trade-news admin`
  (только веб), `trade-news collect <source>`, `trade-news annotate --batches N`.
- Alembic autogenerate рендерит `JSONB(astext_type=Text())`: шаблон миграций уже импортирует
  `Text`, но сгенерированный файл надо прочитать глазами.
- Смена `PROMPT_VERSION` переразмечает только свежие записи (`llm.max_item_age_hours`);
  чтение везде берёт последнюю разметку записи (`views.latest_annotation_ids`).
